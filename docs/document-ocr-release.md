# Eight document extraction APIs — release gate

This release replaces the earlier four-provider OCR plan. The eight native KYCProbe modules are UAE trade licence, passport/TD3 MRZ, UAE power of attorney, UAE utility bill, cheque, memorandum of association, articles of association, and Emirates ID/TD1 MRZ. All are disabled in production until the shared gate below passes. Each module has its own customer entitlement and tiered price; they are excluded from Forms until a document-input mapping is designed and tested.

## Processing contract

- `POST /service/{module}` accepts one `file` and an `Idempotency-Key` (16–128 allowed characters). Emirates ID alone accepts one `additional_file` for the other side. PDF, PNG and JPEG are accepted, up to 25 MiB combined and the service page limit. Invalid content is rejected before queueing.
- The API reserves credit only after authentication and entitlement checks. HTTP 202 returns the job, status and result URLs. Repeated requests with the same key and files reuse the job and refund the duplicate admission. A terminal extraction failure refunds the reservation; successful and review-required extraction results settle it once. The hourly reconciler repairs a worker crash between result storage and settlement.
- The queue worker scans every file with ClamAV, counts pages, calls the dedicated UAE North Document Intelligence `prebuilt-layout` resource, stores an encrypted OCR checkpoint, then calls the separate document Gemini key **once** for strict JSON structuring. An uncertain paid-call outcome is failed closed rather than retried. The worker has at most two Azure analyses and one Gemini call per job. Dead-lettered jobs require operations review.
- Each result includes all documented fields, verified OCR page evidence, explicit review flags, provider-call counts and a randomly generated transaction ID. Absent scalar fields return `Not Found`; unreadable or unsupported scalar fields return `Not Readable`; absent lists return empty arrays. Document text is treated as untrusted evidence, AI-directed instructions are removed before the model call, and the output is schema-validated and checked against the remaining OCR text. Passport TD3 and Emirates ID TD1 check digits are calculated in code. MRZ integrity does not establish physical-document or chip authenticity.
- Emirates ID Azure figure crops are classified during the one final Gemini call. Only uniquely identified, high-confidence portrait or signature crops are saved. Missing portrait or ambiguous crops require review. Private crop links expire in five minutes.
- Inputs, OCR text, results and crops use dedicated encrypted private Blob storage. The API stops serving them after 30 days; an hourly purge removes expired jobs and data. Blob lifecycle deletion is a backup. The Document Intelligence analyze result is explicitly deleted after retrieval.
- Pending and expiry rows are indexed by due time, so settlement and deletion jobs read only due work as volume grows. A job that remains unfinished for two hours is failed and refunded rather than leaving credit reserved indefinitely.

## Before enabling production

1. Obtain a **separate Gemini project and API key** for document extraction. Place it through Admin → API engine → Document OCR AI Structuring; confirm the write-only credential is present. The adverse-media Gemini key must remain separate.
2. Obtain **redacted but representative samples** for every document type. Include English/Arabic trade licences, a valid and invalid TD3 passport MRZ, both Emirates ID sides as a single PDF and as two files, and a valid and invalid TD1 MRZ where available. Include scans of varied quality and a non-matching document for each service. Do not use real customer identity data in test fixtures.
3. Run real Azure + Gemini extraction against the samples. Verify every requested field against the source image, page evidence, date formats, `Not Found`/`Not Readable` handling, wrong-document rejection, MRZ checks, portrait/signature crops, and review flags. Include prompt-injection text in redacted test documents and confirm it neither changes the field values nor the response shape. Set and record an acceptance threshold with the product owner; no accuracy claim is made from the synthetic unit tests.
4. Provision the isolated OCR platform with `infrastructure/api-document-ocr-platform.bicep` in UAE North. Create two independent random 256-bit Key Vault secrets: `document-ocr-data-key` and `document-ocr-download-key`. Confirm the S0 Document Intelligence account has local-key auth disabled, all managed-identity roles have propagated, storage is private with shared-key auth disabled, and the ClamAV sidecar reports ready.
   Keep each encryption-key version available for its full 30-day data window; changing the active data key without a migration would make retained records unreadable.
5. Set the GitHub `ai7uae-api` environment variable `DOCUMENT_OCR_ENABLED=true` **only after** the sample and security gates pass. Run the reviewed deployment workflow. It builds a digest-pinned worker image, previews and deploys the isolated platform, then enables all eight API routes, worker, hourly purge job and portal entries together. Keep the variable true for subsequent main-branch deployments.
6. Run authenticated live smoke tests for all eight modules with a disposable customer key. Check API-key denial, module denial, prepaid reservation/refund, idempotent replay, JSON response, five-minute crop URL, deletion after expiry via controlled test clock, queue dead-letter behavior, and customer/admin usage logs. Revoke the disposable key.
7. Monitor OCR queue depth, dead-letter count, worker failures, malware gate, Azure and Gemini call counts, settlement reconciliation, and expiry purge. Hold launch if the worker is not processing or if the final result omits required fields without a review flag.

The CI suite verifies schemas, MRZ math, route admission, entitlement, refund, retry boundaries, encryption, crop-link signatures and Bicep syntax. It does **not** substitute for sample-based extraction accuracy testing.

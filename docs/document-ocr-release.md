# Eight document extraction APIs — release gate

This release replaces the earlier four-provider OCR plan. The eight native KYCProbe modules are UAE trade licence, passport/TD3 MRZ, UAE power of attorney, UAE utility bill, cheque, memorandum of association, articles of association, and Emirates ID/TD1 MRZ. The customer API routes were enabled on 27 October 2026 after the isolated worker and sample checks. Each module has its own customer entitlement and tiered price; they are excluded from Forms until a document-input mapping is designed and tested.

## Ollama migration gate — 1 November 2026

The proposed worker image bundles the Apache 2.0 licensed `qwen3-vl:4b-instruct` vision model for page transcription and local JSON structuring, including Arabic text. It runs on CPU through Ollama bound to loopback, with one request at a time per replica. The existing private queue, encrypted 30-day store, malware gate, field schemas, evidence checks, MRZ checks, billing, and private Emirates ID crop links remain. New local installations default to Ollama. Production keeps its Azure/Gemini selection until the reviewed rollout sets the GitHub environment variable `DOCUMENT_OCR_FORCE_OLLAMA=true`; that override routes all eight APIs to Ollama, while already queued Azure jobs retain their recorded engine. Drain any pre-existing Paddle jobs before replacing the worker image. The API rejects new Ollama admissions until the bundled worker records the deployed image digest and model as available. The OCR worker scales from zero to ten replicas on queue length. Queue visibility renews while CPU processing runs, and queued-job reconciliation allows a seven-day backlog window.

In the Ollama path, Emirates ID MRZ comes from Ollama page transcription and TD1 check digits are verified in code. Tesseract remains available for Azure engine jobs during the staged rollout.

Before enabling the production override, the focused pull request must pass the bundled-image build and CPU-constrained smoke that exercises vision OCR, all eight structured schemas, and an injected-document example. Run representative, redacted samples for every document type, including a real utility bill, valid and invalid passport/Emirates ID MRZ, Emirates ID front/back crops, Arabic text, poor scans, and wrong-document controls. Check every populated field against its source and review flags. Then use the reviewed main-branch deployment workflow, wake the new worker with a harmless queue message, verify its capability record and image digest, and submit authenticated disposable-key jobs for all eight routes. Keep the old pipeline running until those checks pass. No accuracy claim follows from synthetic unit or smoke tests alone.

## Historical Azure/Gemini processing contract

- `POST /service/{module}` accepts one `file` and an `Idempotency-Key` (16–128 allowed characters). Emirates ID alone accepts one `additional_file` for the other side. PDF, PNG and JPEG are accepted, up to 25 MiB combined and the service page limit. Invalid content is rejected before queueing.
- The API reserves credit only after authentication and entitlement checks. HTTP 202 returns the job, status and result URLs. Repeated requests with the same key and files reuse the job and refund the duplicate admission. A terminal extraction failure refunds the reservation; successful and review-required extraction results settle it once. The hourly reconciler repairs a worker crash between result storage and settlement.
- The queue worker scans every file with ClamAV, counts pages, calls the dedicated UAE North Document Intelligence account (`prebuilt-idDocument` for passports and `prebuilt-layout` for the other modules), stores an encrypted OCR checkpoint, then calls the separate document Gemini key **once** for strict JSON structuring. An uncertain paid-call outcome is failed closed rather than retried. The worker has at most two Azure analyses and one Gemini call per job. Dead-lettered jobs require operations review.
- Each result includes all documented fields, verified OCR page evidence, explicit review flags, provider-call counts and a randomly generated transaction ID. Absent fields, including lists, return `Not Found`; visibly present but unreadable fields return `Not Readable`. Document text is treated as untrusted evidence, AI-directed instructions are removed before the model call, and the output is schema-validated and checked against the remaining OCR text. Passport TD3 and Emirates ID TD1 check digits are calculated in code. MRZ integrity does not establish physical-document or chip authenticity.
- Emirates ID pages are rendered inside the worker after malware scanning. Local OCR supplies MRZ lines only when every TD1 check digit passes; Gemini sees page images in its one final call and locates portrait and signature regions. Only tight, uniquely identified, high-confidence crops are saved, never a full card image. Missing MRZ, missing portrait, or ambiguous crops require review. Private crop links expire in five minutes.
- Inputs, OCR text, results and crops use dedicated encrypted private Blob storage. The API stops serving them after 30 days; an hourly purge removes expired jobs and data. Blob lifecycle deletion is a backup. The Document Intelligence analyze result is explicitly deleted after retrieval.
- Pending and expiry rows are indexed by due time, so settlement and deletion jobs read only due work as volume grows. A job that remains unfinished for two hours is failed and refunded rather than leaving credit reserved indefinitely.

## Historical 27 October production enablement

1. Obtain a **separate Gemini project and API key** for document extraction. Place it through Admin → API engine → Document OCR AI Structuring; confirm the write-only credential is present. The adverse-media Gemini key must remain separate.
2. Obtain **redacted but representative samples** for every document type. Include English/Arabic trade licences, a valid and invalid TD3 passport MRZ, both Emirates ID sides as a single PDF and as two files, and a valid and invalid TD1 MRZ where available. Include scans of varied quality and a non-matching document for each service. Do not use real customer identity data in test fixtures.
3. Provision the isolated OCR platform from the reviewed main-branch `deploy-api.yml` workflow with `provisionDocumentOcrPlatform=true` while the environment variable `DOCUMENT_OCR_ENABLED` is still unset. This creates the dedicated UAE North S0 account, private storage and worker identity without enabling customer routes. Confirm the account has local-key auth disabled and storage has shared-key auth disabled. Obtain explicitly scoped temporary QA access to those new resources; never use the bank-statement resource as a fallback.
4. Run real Azure + Gemini extraction against the samples. Verify every requested field against the source image, page evidence, date formats, `Not Found`/`Not Readable` handling, wrong-document rejection, MRZ checks, portrait/signature crops, and review flags. Include prompt-injection text in redacted test documents and confirm it neither changes the field values nor the response shape. Set and record an acceptance threshold with the product owner; no accuracy claim is made from the synthetic unit tests. Create two independent random 256-bit Key Vault secrets: `document-ocr-data-key` and `document-ocr-download-key`.
   Keep each encryption-key version available for its full 30-day data window; changing the active data key without a migration would make retained records unreadable.
5. Set `DOCUMENT_OCR_WORKER_ENABLED=true` in the `ai7uae-api` GitHub environment while `DOCUMENT_OCR_ENABLED` remains unset. Run the reviewed deployment workflow. Verify the digest-pinned worker starts from a harmless queue message, the ClamAV sidecar passes its readiness scan, dead-letter handling works, and the hourly purge job is present. Remove temporary QA access after validation.
6. Set `DOCUMENT_OCR_ENABLED=true` **only after** the sample and worker gates pass. Run the reviewed deployment workflow and keep this variable true for subsequent main-branch deployments. This enables the eight customer API routes and portal entries.
7. Run authenticated live smoke tests for all eight modules with a disposable customer key. Check API-key denial, module denial, prepaid reservation/refund, idempotent replay, JSON response, five-minute crop URL, deletion after expiry via controlled test clock, queue dead-letter behavior, and customer/admin usage logs. Revoke the disposable key.
8. Monitor OCR queue depth, dead-letter count, worker failures, malware gate, Azure and Gemini call counts, settlement reconciliation, and expiry purge. Hold launch if the worker is not processing or if the final result omits required fields without a review flag.

The CI suite verifies schemas, MRZ math, route admission, entitlement, refund, retry boundaries, encryption, crop-link signatures and Bicep syntax. It does **not** substitute for sample-based extraction accuracy testing.

### Current production state — 27 October 2026

The isolated S0 Azure platform is provisioned in UAE North. The OCR worker, ClamAV sidecar, hourly purge job, and all eight customer API routes are enabled. The dedicated worker consumed a harmless queue smoke message without retry or restart; the purge job completed a manual run. The deployment workflow completed with `DOCUMENT_OCR_ENABLED=true`, and the live API readback showed `DOCUMENT_OCR_PRODUCTION_ENABLED=1`. The platform workflow's GitHub identity could not create resources or role assignments; a one-time, user-approved Owner-account deployment of the reviewed Bicep completed the 21 new-resource creations with no existing-resource updates or deletions. A second reviewed, one-resource Owner bootstrap created only the OCR purge job. Temporary queue and sample-testing roles were removed. See `docs/document-ocr-sample-qa.md` for sanitized live sample outcomes.

The dedicated OCR worker retains `Key Vault Secrets User` on the shared AI7 UAE vault. Narrowing it to two OCR secrets was proposed, and the owner elected to keep the existing vault-wide assignment. This access should be reconsidered before onboarding regulated customer documents at scale.

The deploy identity cannot create a Container Apps Job at resource-group scope. `infrastructure/api-document-ocr-purge-bootstrap.bicep` is a one-time, single-resource bootstrap for the dedicated OCR purge job. Preview this template and require exactly one `Create` for that job with no other creates, modifications or deletions. After it exists, grant the deploy identity only `Microsoft.App/jobs/read` and `Microsoft.App/jobs/write` at that job's resource scope. Subsequent updates use the reviewed main-branch API deployment workflow.

## Controlled sequence

1. Approve the dedicated CIDRs, cost/quota and operator scope. Confirm no overlapping corporate or peered routes. Build all Bicep templates, review what-if at the exact proposed source, then separately authorize creation of the network, storage/private endpoints and manual probe job. Capture and workspace policies stay off.
2. Verify new environment creation, endpoint approval, private DNS zone links, storage `publicNetworkAccess=Disabled`, disabled shared keys and public Blob access. Start the manual probe job with an immutable reviewed image. Retain its execution ID, digest, end time and sanitized `case_manager_private_path_verified` log. A successful health endpoint or ARM property alone is insufficient.
3. Deploy new named API/screenshot resources in `parallelDeployment=true`. They use internal ingress and no shared queue consumers. Keep all real traffic on the old API. Use only a disposable workspace and synthetic subjects; before async QA, provision isolated QA queues/stores and credentials under a separate reviewed plan. This template does not make the shared BSA/OCR/Forms queues safe for parallel consumers.
4. Plan new environment certificates for `api.ai7uae.com` and `app.kycprobe.com`. Verify certificate issuance, ownership TXT validation, app binding and the new environment ingress before DNS changes. The `api` CNAME is in the KYCProbe `ai7uae.com` Azure zone; `app.kycprobe.com` is controlled at GoDaddy. Preserve mail records and the apex/`www` website. Do not point either host to an app without its environment-scoped certificate.
5. At the approved handoff, stop new asynchronous submissions, inspect and drain the old Forms and adverse-media deep-research queues, stop the old API's inline workers, then enable exactly one new API consumer. Drain BSA and OCR queues, disable each old queue-scaled worker and the old OCR purge schedule before enabling new uniquely named workers/jobs. Merchant screenshot traffic follows the API. GDELT ingest remains separate. Record queue depths, job revisions, callback state and the single active consumer for each queue.
6. Use the exact image digest and new environment certificates in the API what-if. Review all proposed updates/deletes. Run authenticated private-runtime QA with isolated async stores, one disposable workspace, exact artifacts, all service results, 180 QPM mixed load, deletion lag and rollback **before** DNS/traffic promotion. Keep the public API contract, billing and source stores unchanged. The DNS change needs its own approval after these gates pass.

Before real cases exist, routing back to the old environment is possible after draining new consumers. Once cases exist, restore only a compatible prior digest **in the new VNet environment**; the old environment cannot access the private Case Manager account. `CASE_MANAGER_EMERGENCY_OFF=true` stops new capture and `CASE_MANAGER_MAINTENANCE_ENABLED=true` keeps purge and reconciliation running. Never delete the store or stop maintenance to roll back.

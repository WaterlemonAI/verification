# Adverse Media Advance: signed incident report API

`POST /internal/adverse-media-advance/report-test` runs the source, screening, incident grouping, narrative, and PDF steps in one request. It is an internal QA endpoint, controlled by `ADVERSE_MEDIA_JEV_API_ENABLED=true` and a bearer value in `ADVERSE_MEDIA_JEV_SCREENING_TOKEN` (at least 32 characters). The customer Advance route is unchanged and remains disabled for this candidate.

The minimum request is the subject. The report route supplies `adverse_profile: "all"`, global geography, the most recent 30 calendar days, `max_articles: 40`, and `max_archive_postings: 500` when omitted. Callers may supply an entity type and up to three aliases, a period of no more than 30 days, and tighter article/posting caps. The route generates up to one Arabic and one Hindi name transliteration, then searches the primary name, aliases, and each generated variant. Callers may supply validated `subject.transliterations: {"ar":["..."],"hi":["..."]}` instead; the exact submitted values are searched. The [integrated test API](adverse-media-jev-integrated-test-api.md) retains its explicit request schema and does not generate variants itself.

```json
{"subject":{"name":"Example Trading LLC"}}
```

One call returns the finalized public JSON and signed PDF in `report.pdf_base64`; no separate summary, incident assignment, or PDF-finalization request is needed. The local QA re-signing script upgraded artifacts produced before the last template and source-warning fixes. It is not part of the API request path.

The server reads discovery and screening credentials, and `MISTRAL_API_KEY` (or the server-side `adverse-media-summary` key), without accepting provider keys from the caller. A bounded name-variant call precedes discovery when variants are not supplied. It finalizes the screening JSON before requesting a short narrative summary, then projects only public fields and renders the PDF from that projection. When no adverse incident group is established, the summary is deterministic and makes no narrative model call. Public JSON and the PDF expose no model, vendor, provider trace, internal tool reference, screening probabilities, or raw article body. The response includes `contract: "adverse-media-incident-report-v1"`, subject, `search_names` (the primary name, aliases, and transliterations actually searched), period, summary, coverage counts, retained articles, incident buckets, disclaimer, and `report` metadata plus `pdf_base64`. Decode `report.pdf_base64` to obtain the signed PDF; verify its bytes against `report.sha256`.

When discovery returns no selected articles, the report returns `screening_result: "Safe"`, empty article and incident arrays, and a signed, one-page PDF stating **“No public adverse media evidence found in the sources searched during the stated period.”** It lists the exact searched name spellings. Safe means no relevant public adverse media evidence was found in the sources actually searched; it is not a guarantee that no adverse information exists. The normal API rejects an archive snapshot whose committed watermark does not cover the full requested day before discovery can return Safe. If the QA-only archive access fallback was used, the result remains `Safe`, with `status: "completed_with_source_gap"`, `coverage.source_coverage_status: "incomplete"`, and `coverage.unavailable_sources: ["archived_media_index"]`; the PDF names that source and limits Safe to the sources searched. If articles were selected but no usable body can be extracted, the API still returns `424 evidence_unavailable`; it never converts an extraction failure into Safe.

Article labels are limited to `adverse | non-adverse | inconclusive` and `direct | indirect | inconclusive`. Unrelated articles are removed from the public register and counted as redundant. Only adverse retained articles can create incident buckets. `incident_id: null` means the article remains in the review section and was not assigned to a distinct adverse incident. The policy catalog is selected by `adverse_profile: "all"`, but per-policy adjudication is not implemented; `policy_evaluation_status` is `not_run`. A successful report must not be interpreted as a completed policy decision.

For reports with incidents, the first PDF page has a separate bucket for each group, adapting to the actual group count. Subsequent pages show article label and evidence charts, a reading guide and disclaimer, and incident/article detail. A Safe result uses the separate one-page template. Every PDF must be digitally signed. In production the API fails before screening if a signing identity is unavailable. `JEV_PDF_SIGNING_KEY_VAULT_URI` and `JEV_PDF_SIGNING_KEY_VAULT_SECRET_NAME` must identify an exportable PKCS#12 certificate secret that the runtime can read. The current QA certificate is self-signed and proves integrity only; it does not establish a trusted KYCProbe signer. The relevant Key Vault's certificate list is inaccessible to the current account, and its visible secret metadata does not identify a document-signing certificate.

Source and report errors return generic public codes: `invalid_request`, `evidence_unavailable`, `cost_limit_reached`, or `report_unavailable`. The local QA runner records detailed errors privately. It measures request latency and calls, and estimates variable cost from current public rates: search at $0.005 per request (two base calls plus two for each searched transliteration), article extraction at 0.05 of a $0.018 plan token per call, screening at a conservative input-byte upper bound of $0.042 per million, name-variant generation and summary at $0.10 per million input/output tokens, and active Container Apps compute for 0.5 vCPU plus 1 GiB at $0.000015 per second. These are modeled marginal charges, not provider invoices; they exclude shared idle capacity, egress, storage, logging, tax, and plan allowances.

The archive branch requires access to both the V2 summary and V1 posting tables. The QA runner uses the Container Apps managed identity for archive and Key Vault reads when run inside the private QA container; `QA_REQUIRE_MANAGED_IDENTITY=true` rejects accidental local execution. The local CLI account lacks Table data read access. Its runner can explicitly record a 403 and use search plus extracted article bodies as a degraded test path. That override is only in the runner; the API's normal archive requirement remains strict. Degraded QA responses set `status: "completed_with_source_gap"` and `coverage.source_coverage_status: "incomplete"`; with no retained media the overall decision is `Safe`, and the signed PDF names the unavailable archived media index and limits the result to the sources searched. A selected article without an extractable body still fails instead of producing Safe. The runner's modeled aggregate cap defaults to $5 and can be lowered for smaller QA batches; it writes response/PDF pairs for successful cases, with a private ledger of calls, timings, and costs.

Run the unit and local route tests with:

```sh
node --test test/adverse-media-jev-integrated.test.mjs test/adverse-media-jev-report-pdf.test.mjs test/adverse-media-jev-ministral-summary.test.mjs test/adverse-media-jev-pdf-signing.test.mjs
```

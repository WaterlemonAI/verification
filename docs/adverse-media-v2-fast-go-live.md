# Adverse Media V2: shorter go-live path

**Source reviewed:** `codex/gdelt-versioned-summary`, 20 November 2026. This is a source and GitHub configuration review, not a fresh Azure readback. No deployment or cloud configuration change was made. Refresh the [last retained Azure validation](gdelt-v2-live-validation-2026-11-20.md) before promotion.

## Execution and two review passes

The first pass checked the customer contract and rollback path. It found that the old global flag could queue article review without a production article resolver and could leave already queued jobs reviewing after rollback. The implementation now requires `archive_review=true` on an undated callback request, advertises readiness only when the queue, worker, V2 archive settings and resolver are configured, and settles a disabled queued review as Inconclusive. Existing deep-research customers stay on their existing path. The public configuration response is uncached so a switch is visible immediately.

The second pass checked the evidence required to activate V2 reads. The old point probe reported fast counts but did not compare them with the full V1 postings. `scripts/gdelt-v2-parity.mjs` now requires at least 50 distinct controlled subjects, a fresh contiguous V2 watermark spanning V1, and exact per-subject V1/V2 count agreement. It pages V1 without the synchronous 15-second scan cap, emits only subject hashes and aggregate latency metrics, and exits nonzero on any mismatch. The script is read-only. Use `node scripts/gdelt-v2-parity.mjs --isolated-candidate --subjects-file /approved/path/subjects.json` after the full rebuild; the JSON file contains 50 or more strings or `{ "name": "...", "entity_type": "business|individual", "aliases": ["..."] }` objects. Include the formerly failing high-volume subjects and a mix of zero, ordinary, Arabic and alias cases in the approved input.

**Current release decision:** source can be reviewed for a flags-off deployment after hosted CI. V2 **read activation is blocked** until a fresh full rebuild, independent full-range verification, the 50-subject parity command and a retained end-to-end candidate cohort pass. Full article review is a later release and remains disabled. No source-only test can substitute for those live gates.

**Files in this release:** `lib/adverse-media.mjs` (opt-in and fail-closed profile), `lib/deep-research-queue.mjs` (queued-job rollback), `server.mjs` (readiness gate and uncached configuration), `api/openapi.json` and `api-site/adverse-media.{html,js}` (contract and form), `scripts/gdelt-v2-parity.mjs` (read-only acceptance gate), and focused tests in `test/adverse-media.test.mjs`, `test/deep-research-queue.test.mjs`, `test/gdelt-archive-review.test.mjs`, and `test/gdelt-v2-parity.test.mjs`. Existing V2 ingestion, summary, manifest, verifier, Bicep and workflow files require no source change for this release.

## Decision: release in two milestones

| Milestone | Customer result | Required before activation |
| --- | --- | --- |
| **M1 — V2 archive lookup** | Fast point lookup replaces the slow V1 scan for undated searches. Standard and Search+ keep Brave and the dated public-GDELT fallback. A nonempty archive without article review stays **Inconclusive**; a confirmed direct adverse finding from another source stays **Unsafe**. | Complete and verify the V2 rebuild over the **current stored V1 range**, prove V1/V2 parity and no false Safe, and measure customer-visible profile changes. No article-text provider is needed. |
| **M2 — full article review** | Explicitly opted-in asynchronous requests page all stored V1 mentions, resolve articles, and return a final profile, PDF, signed callback and owner-scoped evidence pages. | Approved article-text source and rights, Gemini adjudication, budget/concurrency limits, queued-job kill switch and real-article end-to-end proof. Keep `GDELT_ARCHIVE_REVIEW_ENABLED=false` until then. |

**Last retained state:** only 20 historical V2 intervals plus one current interval were independently verified out of 2,706; V2 reads were off. V1 began 22 October 2026, about four weeks before the retained 20 November readback. This is not today's Azure state. The production server currently supplies no `adverseArticleResolver`; the updated readiness guard rejects M2 requests even if its flag is turned on.

## Gaps in the original sequence

1. **It made article access a prerequisite for M1.** The V2 read and archive-review flags are independent. M1 can safely return Inconclusive for unreviewed archive mentions, provided the change in outcomes is measured and communicated. `status=completed` means source retrieval completed, not that the profile is Safe.
2. **It treated a year of backfill as a launch gate.** Undated searches cover all history **actually stored** in Azure. The response/report must show its real start/end. Continue the 365-day backfill after launch; do not market a year before the contiguous watermark reaches it.
3. **It waited for a scheduled weekend transition.** Test watermark/cache invalidation with a controlled transition and verify one new daily dual-write interval before activation. Monitor the next real Saturday run after launch.
4. **It blurred parity and paid API testing.** Keep at least 50 read-only V1/V2 subject count comparisons, but use a smaller labeled, retained end-to-end API cohort for standard and Search+. Expand that cohort if any mismatch or false Safe appears.
5. **It called a global switch a canary.** The API has a single active revision and global flags. Use the existing internal-only candidate-app pattern before a staffed production switch. A true tenant canary requires new owner gating.

## M1 critical path — publish and activate the V2 lookup

1. **Publish foundation source with both flags off.** Run full repository and hosted CI on the reviewed SHA. Confirm `GDELT_V2_READ_ENABLED=false` and `GDELT_ARCHIVE_REVIEW_ENABLED=false` in the production environment **before merging**, because a push to `main` triggers API deployment. Record the exact source SHA, workflow run/attempt, what-if, ACR digest, deployed revision and flag readback. No provider purchase, new secret or M2 code is required for this step.
2. **Start dual-write and rebuild while M2 is developed.** Under separately authorized production operations, read back the selected subscription/resource group, two V2 tables, job identity, image digests, V1/V2 watermarks and job executions. Use the [existing GDELT job workflow](../.github/workflows/deploy-gdelt-backfill.yml) with the reviewed `main` digest and `GDELT_V2_DUAL_WRITE=true`, accepting only expected job changes in what-if. Verify one new daily interval has a committed V2 manifest. Run the existing resumable `scripts/gdelt-index-v2-rebuild.mjs` against stored ZIPs; do not wait for the weekly backfill schedule.
3. **Verify the full fresh stored range.** Run `scripts/gdelt-index-v2-verify.mjs` over every V1 interval, in bounded chunks until `more=false`. The contiguous V2 start/end and committed count must cover a **fresh** V1 watermark, with no unexplained digest, manifest, source-count or interval-bit difference. Run `scripts/gdelt-v2-parity.mjs` against at least 50 controlled zero, ordinary, high-volume, Arabic/alias and previously failing subjects; require `mismatches=0`. In the isolated candidate, reprocess a controlled interval and simulate an older backfill to prove idempotence and cache/snapshot invalidation; this replaces waiting for the next Saturday. The retained 7–47 ms partial point probes do not satisfy this gate.
4. **Run a compact real API cohort on the isolated candidate digest.** Include standard/Search+, zero-mention, high-volume, confirmed adverse, neutral/namesake, ambiguous, provider-429 and explicit historical date-gap cases. Retain sanitized request/source attempts, JSON, PDF hash, profile, archive snapshot, cost and reviewer label. Prove undated Azure-only requests make zero public DOC calls, dated gaps make at most three direct DOC attempts, and Search+ adds publishers. Compare profiles with V1. A nonempty unreviewed V2 archive should become Inconclusive, not Safe; a material increase in Inconclusive outcomes needs a product decision before the global switch.
5. **Activate only V2 reads.** From reviewed `main`, use the existing production API workflow with `GDELT_V2_READ_ENABLED=true` and `GDELT_ARCHIVE_REVIEW_ENABLED=false`. Verify digest, revision and flags. In a staffed window, run controlled authenticated cases and watch archive origin/window, status/profile/eligibility, V2 errors, Azure Table throttling, public-DOC calls, PDF success and p50/p95/p99 for lookup and end-to-end API. The existing p95 target of 250 ms applies to a ready exact-name V2 lookup only. Roll back on a count mismatch, false Safe, unexpected profile change or sustained error/latency regression.

**M1 exit:** current V1/V2 parity verified, no false Safe in the labeled cohort, source status distinguished from profile eligibility in JSON/PDF/Flo, live digest/flags read back, and V1 rollback demonstrated. M1 does not claim every article was read or that Azure stores one year.

## M2 critical path — complete article review later

1. **Article evidence and adjudication.** After an approved contract for URL/article matching, English/Arabic coverage, retention rights and price, create `lib/gdelt-article-evidence-provider.mjs`. Allowlist its endpoint; do not scrape arbitrary GKG URLs. Add bounded Gemini article review to `lib/ai7uae-gemini-adverse-api.mjs`, treating source text as untrusted. Require a supported source quote and subject-role finding; otherwise leave the article unresolved. Wire the resolver into production `server.mjs`, not only a test injection.
2. **Protect existing customers and bound work.** The explicit request-level opt-in and queued-job kill switch are implemented; verify them again with the real resolver before M2. Add one per-review provider/Gemini budget, bounded concurrency/page time and a terminal Inconclusive result on cap or outage in `lib/deep-research-queue.mjs` and `lib/gdelt-archive-review.mjs`. The current queue message lasts seven days and permits up to 10,000 review-page deliveries; measure high-volume subjects before promising an SLA.
3. **Prove the full path with real articles.** On the isolated candidate, test clean, direct-adverse, namesake, ambiguous, Arabic, missing-text, provider-failure, common-name and changed-snapshot cases. Every finished review must reconcile V1 postings to its V2 snapshot and expose all decisions through owner-authenticated pages. Confirm one final report and signed callback, no repeated paid search or second customer charge on page/report/callback retry, and agreement across JSON/PDF/evidence/callback. Measure cold/warm p50/p90/p95/p99, provider calls, Gemini tokens, Azure operations and cost per subject; set a spend and latency ceiling from the evidence. Missing plausible article text remains Inconclusive.
4. **Enable only after acceptance.** Use the reviewed workflow to set `GDELT_ARCHIVE_REVIEW_ENABLED=true` while V2 reads stay on. Run controlled explicit opt-in standard and Search+ jobs covering Safe, Unsafe and Inconclusive. Check full evidence, PDF, signed callback, budget, queue/dead-letter state and rollback of pending jobs. Request-level opt-in protects compatibility; add a workspace allowlist if limited-customer availability is required.

**M2 exit:** no false Safe in labeled cases, no cross-owner evidence access, no unpriced or duplicate provider call/charge, bounded terminal behavior for high-volume cases, and tested queued-job rollback. GKG metadata alone cannot clear a nonempty archive as Safe.

## Off the critical path and rollback

- Extending stored history to 365 days and observing the next scheduled weekend run move to post-activation monitoring, provided actual coverage dates are shown and a controlled watermark-change test passes.
- Incremental reuse of article decisions across **new** daily snapshots can follow M2 if the measured first cohort meets the approved cost/latency ceiling. The current review ID changes with each snapshot and otherwise re-reviews history; if that exceeds the ceiling, incremental reuse becomes a prelaunch fix.
- No new posting database, queue, Azure job, identity or broader GDELT write grant is required for the first release.
- **M1 rollback:** turn `GDELT_V2_READ_ENABLED=false` and redeploy a reviewed compatible digest/configuration; verify V1 profiles and reports. Keep ZIPs, V2 tables and audit data.
- **M2 rollback:** turn `GDELT_ARCHIVE_REVIEW_ENABLED=false`. The worker skips the article step for already queued jobs and returns an Inconclusive review reason through the normal report/callback path. Confirm this with the real resolver and queue before M2 activation; preserve settled results and audit records.

Retain source SHA, CI/deployment attempts, digest/revision, V1/V2 watermarks and verifier output, 50-subject parity, labeled JSON/PDF/callback hashes, cost/latency measurements, flag readback and rollback evidence. Keep credentials, customer PII and unlicensed article text out of logs and CI artifacts. This plan does not authorize cloud reads, deployment, provider purchase, RBAC changes or customer data use.

## Execution and two review passes

The first pass checked the customer contract and rollback path. It found that the old global flag could queue article review without a production article resolver and could leave already queued jobs reviewing after rollback. The implementation now requires `archive_review=true` on an undated callback request, advertises readiness only when the queue, worker, V2 archive settings and resolver are configured, and settles a disabled queued review as Inconclusive. Existing deep-research customers stay on their existing path. The public configuration response is uncached so a switch is visible immediately.

The second pass checked the evidence required to activate V2 reads. The old point probe reported fast counts but did not compare them with the full V1 postings. `scripts/gdelt-v2-parity.mjs` now requires at least 50 distinct controlled subjects, a fresh contiguous V2 watermark spanning V1, and exact per-subject V1/V2 count agreement. It pages V1 without the synchronous 15-second scan cap, emits only subject hashes and aggregate latency metrics, and exits nonzero on any mismatch. The script is read-only. Use `node scripts/gdelt-v2-parity.mjs --isolated-candidate --subjects-file /approved/path/subjects.json` after the full rebuild; the JSON file contains 50 or more strings or `{ "name": "...", "entity_type": "business|individual", "aliases": ["..."] }` objects. Include the formerly failing high-volume subjects and a mix of zero, ordinary, Arabic and alias cases in the approved input.

**Current release decision:** source can be reviewed for a flags-off deployment after hosted CI. V2 **read activation is blocked** until a fresh full rebuild, independent full-range verification, the 50-subject parity command and a retained end-to-end candidate cohort pass. Full article review is a later release and remains disabled. No source-only test can substitute for those live gates.

## Gaps in the original sequence

1. **It made article access a prerequisite for M1.** The V2 read and archive-review flags are independent. M1 can safely return Inconclusive for unreviewed archive mentions, provided the change in outcomes is measured and communicated. `status=completed` means source retrieval completed, not that the profile is Safe.
2. **It treated a year of backfill as a launch gate.** Undated searches cover all history **actually stored** in Azure. The response/report must show its real start/end. Continue the 365-day backfill after launch; do not market a year before the contiguous watermark reaches it.
3. **It waited for a scheduled weekend transition.** Test watermark/cache invalidation with a controlled transition and verify one new daily dual-write interval before activation. Monitor the next real Saturday run after launch.
4. **It blurred parity and paid API testing.** Keep at least 50 read-only V1/V2 subject count comparisons, but use a smaller labeled, retained end-to-end API cohort for standard and Search+. Expand that cohort if any mismatch or false Safe appears.
5. **It called a global switch a canary.** The API has a single active revision and global flags. Use the existing internal-only candidate-app pattern before a staffed production switch. A true tenant canary requires new owner gating.

## M2 critical path — complete article review later

1. **Article evidence and adjudication.** The Event Registry adapter, allowlisted endpoint, bounded Gemini article reviewer, production server wiring, Key Vault secret reference and shared cost reservation are now implemented behind the off-by-default flag. A standalone 100-URL pilot and one live Node adapter call confirm the extraction response shape, including Arabic body and canonical URL. Before activation, put a paid-plan key in Key Vault, confirm rights and external processing, and run controlled subject-level Gemini decisions. Missing body, uncertain canonical attribution, unsupported quote or cost denial must stay unresolved.
2. **Protect existing customers and bound work.** The explicit request-level opt-in and queued-job kill switch are implemented. The worker now reviews four postings per queue delivery; a configurable posting cap defaults to 200, and Event Registry/Gemini requests share the existing USD 0.14 provider reservation ceiling. Budget denial or a subject above the cap settles Inconclusive. Verify real queue visibility, retry and callback timing with the new resolver; measure high-volume subjects and agree product pricing before increasing the ceiling or promising an SLA.
3. **Prove the full path with real articles.** On the isolated candidate, test clean, direct-adverse, namesake, ambiguous, Arabic, missing-text, provider-failure, common-name and changed-snapshot cases. Every finished review must reconcile V1 postings to its V2 snapshot and expose all decisions through owner-authenticated pages. Confirm one final report and signed callback, no repeated paid search or second customer charge on page/report/callback retry, and agreement across JSON/PDF/evidence/callback. Measure cold/warm p50/p90/p95/p99, provider calls, Gemini tokens, Azure operations and cost per subject; set a spend and latency ceiling from the evidence. Missing plausible article text remains Inconclusive.
4. **Enable only after acceptance.** Use the reviewed workflow to set `GDELT_ARCHIVE_REVIEW_ENABLED=true` while V2 reads stay on. Run controlled explicit opt-in standard and Search+ jobs covering Safe, Unsafe and Inconclusive. Check full evidence, PDF, signed callback, budget, queue/dead-letter state and rollback of pending jobs. Request-level opt-in protects compatibility; add a workspace allowlist if limited-customer availability is required.

**M2 exit:** no false Safe in labeled cases, no cross-owner evidence access, no unpriced or duplicate provider call/charge, bounded terminal behavior for high-volume cases, and tested queued-job rollback. GKG metadata alone cannot clear a nonempty archive as Safe.

## Off the critical path and rollback

- Extending stored history to 365 days and observing the next scheduled weekend run move to post-activation monitoring, provided actual coverage dates are shown and a controlled watermark-change test passes.
- Incremental reuse of article decisions across **new** daily snapshots can follow M2 if the measured first cohort meets the approved cost/latency ceiling. The current review ID changes with each snapshot and otherwise re-reviews history; if that exceeds the ceiling, incremental reuse becomes a prelaunch fix.
- No new posting database, queue, Azure job, identity or broader GDELT write grant is required for the first release.
- **M1 rollback:** turn `GDELT_V2_READ_ENABLED=false` and redeploy a reviewed compatible digest/configuration; verify V1 profiles and reports. Keep ZIPs, V2 tables and audit data.
- **M2 rollback:** turn `GDELT_ARCHIVE_REVIEW_ENABLED=false`. The worker skips the article step for already queued jobs and returns an Inconclusive review reason through the normal report/callback path. Confirm this with the real resolver and queue before M2 activation; preserve settled results and audit records.

Retain source SHA, CI/deployment attempts, digest/revision, V1/V2 watermarks and verifier output, 50-subject parity, labeled JSON/PDF/callback hashes, cost/latency measurements, flag readback and rollback evidence. Keep credentials, customer PII and unlicensed article text out of logs and CI artifacts. This plan does not authorize cloud reads, deployment, provider purchase, RBAC changes or customer data use.

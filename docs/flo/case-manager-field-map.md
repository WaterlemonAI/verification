# Flo application review dashboard: field map

This maps the authenticated buyer case response (`GET /portal/api/flo/cases/:id`) to the review screen. The reference image supplies layout ideas; it is not a source of case facts. A blank, failed, or unavailable value stays visibly blank, failed, or unavailable. Flo has no qualification score, turnover model, universal risk level, assessment task list, or messaging thread, so the dashboard does not invent them.

| Review area | Existing fields | Display and decision rule |
| --- | --- | --- |
| Header | `customer_reference`, `application_id`, `flow_id`, `template_version`, `status`, `supplier_email`, `created_at`, `submitted_at` | Case identity, lifecycle, and supplier contact; distinguish diagnostic from supplier submission. |
| Case provenance | `workspace_id`, `definition_hash`, `updated_at`, `expires_at`, `link_expires_at`, `link_redeemed_at`, `prefill` | Keep operational provenance in the case record. Show meaningful link prefill and timestamps; do not present link expiry as case expiry. |
| Evidence readiness | `draft.supplierType`, `draft.authorityBasis`, `draft.vatRegistered`, `documents[].type`, `documents[].diagnostic_label` | Required document types from the published flow's rules, with present/missing count. A substitute or test sample is **present but not acceptable evidence**; do not call this a compliance percentage. |
| Decision brief | Required-document gaps, `preview_issues[]`, `comparisons[]`, `documents[].extraction_state`, `checks[].transport/coverage/business_result/reason_codes`, `diagnostic` | Prioritize missing evidence and explicit errors; show review signals and unavailable checks separately. A transport success is not a clearance. |
| Legal identity | `draft.supplierType/tradingName/formerNames`, `draft.business_name/licence_number/company_type`, licence/formation/incorporation/VAT extraction results, `facts[]` | Show declared or buyer-inferred values with source; link to the evidence document. |
| People and authority | `draft.representativeEmail/Phone/Title`, `draft.identityType/authorityBasis/ownershipComplete/owners/meetingAvailability`, `draft.stakeholders`, `subjects[]`, identity/POA/board-resolution extraction | Separate declarations from extracted and screened subject facts. |
| Premises | `draft.locationEvidenceType/registeredAddressSame/operatingAddress/fulfilmentLocations/addressChanges/addressChangeExplanation`, location evidence and Ejari extraction, address comparisons | Missing premises remains a blocker; Ejari is `not_run` without evidence. |
| Tax and banking | `draft.vatRegistered/vatReason`, VAT/corporate-tax files, bank document extraction, `draft.iban`, IBAN/VAT/authenticity checks | Corporate tax is not VAT; a test bank letter is not bank-issued proof. |
| Operations and procurement | `draft.website/siteActivities/supplyType/supplyDescription/staffCount/unusualCapacity/capacityDetail/goodsOrigin/goodsRights/goodsRightsDetail/intermediary/intermediaryDetail/priceExplanation/recommendationNote`, legacy `draft.activities/website_url/operating_address` | Show supplier answers without creating an unsupported turnover or industry score. |
| Payment and changes | `draft.thirdPartyPayments/thirdPartyDetail/cashPayment/cashDetail/keyPersonChanges/keyPersonExplanation` | Show declared signals and missing explanations. |
| Declarations | `draft.accuracyDeclaration/screeningConsent/controlledTest/testDeclaration`, `preview_ready_at`, `submitted_at` | Explicitly distinguish reviewed, submitted, and diagnostic states. |
| Documents and inbuilt reviewer | `documents[].document_id/type/mime_type/size/sha256/scan_result/uploaded_at/extraction_state/extraction_reason/extraction_result/diagnostic_label` | Authenticated in-page PDF/image preview, document list, metadata, extraction values, and source-linked checks. Never embed an external document URL. |
| Assessments | `checks[]`, `subjects[]`, `facts[]`, `comparisons[]`, `preview_issues[]`, `gemini_review`, `check_history[]` | Show service, subject, transport, coverage, result, reason codes, and provenance; retain failed and `not_run` states. |
| Reports and activity | `reports[]`, `events[]`, `diagnostic`, `configuration.callback_url` | Link retained PDF/HTML/JSON reports; show decisions, corrections, callback attempts/deliveries, and diagnostic outcome. Never expose callback secrets. |
| Flow routing | `configuration.enabled/brand_name/callback_url/success_url/failure_url/updated_at` | Show the configured brand and callback destination for buyer review; the configuration snapshot is part of the case, not a live admin setting. |

The classic `kys-v1` flow uses `draft.business_name/licence_number/company_type/activities/registered_address/operating_address/iban/website_url/stakeholders` and `trade_licence`, `formation_document`, `bank_letter` document types. The supplier flow uses the camel-case fields above. The same review shell must support both without substituting one flow's requirements for another's.

# Al Naboodah document OCR and consistency contract

This contract applies to the unpublished Al Naboodah Flo draft. Every uploaded active document is processed before supplier submission. OCR is stored as source evidence, with document ID, SHA-256, upload time, extraction status and model; it does not authenticate a document. `Not Found` is the only allowed missing-value marker. All date fields must be unambiguous `YYYY-MM-DD` or `Not Found`; malformed dates fail extraction. Free-text values are bounded strings, not instructions to the model. The buyer must resolve source contradictions before acceptance.

| Upload slot | OCR fields, all emitted as strings | Validity rule and comparison |
|---|---|---|
| UAE trade licence (`trade_licence`) | `company_name_english`, `license_number`, `license_status`, `company_type`, `issue_date`, `expiry_date`, `address`, `business_activity`, `issuer_name`, `stakeholder_names`, `business_manager_names`, `owner_details` | `expiry_date` is mandatory and current. Compare name, number, legal form, status, address and expiry with `uae-trade-licence` API fields `licence_registration_name`, `uae_licence_number`, `legal_type_from_entity`, `license_status`, `licence_registration_address`, `expiration_date`; API licence and MOEC status must be active. Compare OCR manager names with API manager names when available. Screen each identified manager and owner/director. |
| Foreign incorporation (`incorporation_record`) | `company_name`, `registration_number`, `incorporation_date`, `registration_country`, `business_activities`, `issuer_name`, `expiry_date`, `stakeholder_names`, `business_manager_names`, `owner_details` | Reject a printed expired date. A certificate with no expiry may return `Not Found`; compare name, country and activities with supplier and public records. No UAE TLV result is claimed for a foreign entity. Screen printed manager and owner/director names. |
| Natural person or company representative ID (`natural_identity`, `identity_document`) | `identity_type`, `full_name_english`, `document_number`, `nationality`, `expiry_date` | `identity_type` should identify Emirates ID or passport. `expiry_date` is mandatory and current; compare with the separate entered expiry date and legal/representative name. OCR does not establish document authenticity or active government status. |
| Ejari (`ejari`) | Ejari verification API result, including `status` and `fields.tenant_name`, `fields.end_date`, address/building/unit fields | Accept only a PDF and call Ejari API when selected. `fields.end_date` must be present and current. Compare tenant, address and lease period with the supplier and licence. An unavailable API is not a pass. |
| Other address proof (`premises_evidence`) | `evidence_type`, `address`, `tenant_name`, `evidence_date`, `issuer_name`, `document_number`, `period_start_date`, `period_end_date`, `expiry_date` | Supplier chooses utility bill, lease, title deed or other official evidence. OCR must identify a readable address and a type consistent with the choice. A lease needs a current `period_end_date` or `expiry_date`; a utility bill billing period is not a document expiry and must not populate either validity field. A title deed can have no expiry. Buyer separately verifies actual place of business and suitability. |
| Bank confirmation (`bank_letter`) | `business_name`, `account_holder`, `bank_name`, `branch_name`, `bank_country`, `iban`, `account_number`, `issue_date`, `expiry_date`, `letterhead_bank_name` | Required for every supplier under Al Naboodah's preventive policy. `issue_date` must be within one calendar month of submission; any printed expiry must be current. Compare holder with supplier, bank with visible letterhead, and IBAN/holder with the verification API. A home-country letter is retained but not automatically treated as a UAE-bank confirmation at the Decision 13 threshold. |
| Optional bank statement (`bank_statement`) | `account_holder`, `bank_name`, `branch_name`, `bank_country`, `iban`, `account_number`, `issue_date`, `statement_start_date`, `statement_end_date`, `expiry_date` | OCR and compare holder, bank, branch, country, IBAN and account number with the confirmation letter. | Goods origin or right to sell (`goods_origin_evidence`) | `document_kind`, `issuer_name`, `issue_date`, `country_of_origin`, `goods_description`, `expiry_date` | OCR any printed expiry and compare goods/origin with the relevant order review. |
| Payment agreement (`payment_agreement`) | `document_kind`, `issuer_name`, `issue_date`, `subject_name`, `document_number`, `expiry_date` | OCR any printed expiry; compare parties and effective period with the third-party payment explanation. |

Unknown custom document slots use the bounded generic profile: `document_kind`, `issuer_name`, `issue_date`, `expiry_date`, `subject_name`, `document_number`, `address`.

## Field formats and source handling

| Field family | Stored OCR format | Comparison format |
|---|---|---|
| Dates (`*_date`, `expiry_date`) | ISO `YYYY-MM-DD`, or `Not Found` if absent or ambiguous. Never infer a day or month. | Exact calendar date; expiry before the check date fails. Bank-letter issue date is compared with the supplier submission date. |
| Names (company, representative, tenant, account holder, bank) | Printed text as a bounded UTF-8 string, retaining legal suffixes and script. `Not Found` if unreadable. | Unicode and case normalization plus punctuation/space cleanup. Material differences remain source-linked mismatches. |
| Company type / legal form | Printed legal form such as `LLC`, `FZCO`, or its full wording; never replace it with the questionnaire category. | Known equivalent spellings normalize to the same legal form, then compare with the trade-licence API. Unknown forms require buyer review. |
| Licence, registration, ID and account numbers | Printed alphanumeric text as a string, retaining leading zeroes; `Not Found` if unreadable. | Case, spaces and separators normalized for comparison; the original remains visible in evidence. |
| IBAN | Printed IBAN as a string; `Not Found` if absent. No guessed country or check digits. | Uppercase alphanumeric with spaces removed, then run the configured IBAN verification API; provider coverage and bank/holder details are preserved separately. |
| Address | Full printed address as a string, including unit/building, locality, emirate or country where available. | Compare address proof with declared operating address and merchant evidence. A registered office can differ from an operating site and needs buyer explanation/evidence. |
| Activities and goods | Printed activity wording as a string; several activities may be separated by semicolons. | Gemini compares licensed activities to declared supply and merchant observations, recording evidence references and uncertainty. |
| Named stakeholders and manager | `stakeholder_names`: visibly named individual owners, directors or shareholders separated by semicolons. `business_manager_names`: visibly named managers separated by semicolons. `owner_details`: `Name | printed role | printed shareholding percentage`, with semicolon-separated entries and `Not Found` for an absent value. | Combine OCR with the trade-licence verification result, which may expose singular or plural manager fields and structured owner rows. Deduplicate by normalized name, preserve source IDs and printed percentages, and run AML and adverse-media checks for each identified person. Compare printed and API manager names, and block buyer acceptance if a matched owner's printed and API shareholding percentages conflict. A manager is not treated as an owner unless a source says so. When OCR finds no owner or director name, one required fallback field appears in the existing identity stage. Missing or incomplete ownership coverage remains a buyer review issue. |

Gemini returns every field in the fixed profile, including `Not Found` for missing values; extra keys, malformed dates, model-authored claims of authenticity and instructions embedded in a document are rejected. Each extracted field remains tied to the source document ID. API fields remain separate source facts rather than overwriting OCR.

## Decision rules

1. OCR extraction must complete for every active supplier upload. A replaced copy supersedes an earlier upload of the same slot while the earlier source stays in the audit history. A certificate generated by the Ejari API is retained as evidence and is not a separate supplier upload.
2. If an extracted expiry is past, show **“Document Name is expired, please update recent”** with the specific document name. A required expiry that cannot be read blocks submission and acceptance pending a legible replacement. The supplier's separately entered ID/licence expiry must equal the document OCR date.
3. A lease/Ejari past its valid-until date is expired. Every printed expiry is checked even if a lease also has a separate period end; conflicting dates require correction. A title deed or utility bill without printed expiry is not assigned a fabricated date.
4. Deterministic comparisons block buyer acceptance for contradictory supplier and document names, licence and API names, licence number, legal form or expiry; supplier and bank account holder, bank name and letterhead, declared and letter IBAN, and statement IBAN, account number, holder, bank or country; and inactive or unresolved UAE TLV results. Branch and address differences are evidence for buyer review, since bank descriptions and registered versus operating sites can legitimately differ. Gemini receives the source OCR, declared facts and bounded verification API response and flags wider inconsistencies with evidence IDs for buyer review. Its narrative is never an automatic pass.
5. The source record includes the raw upload and the result of each check. A missing API result, OCR failure and genuine mismatch remain distinct statuses. Independent ID authenticity and actual-place-of-business verification still need buyer evidence or suitable external services.

## Gate 1 — finish the release code, with flags off

1. **Foundation publication, optional:** review and merge the current branch only after hosted CI and security review. The production API workflow runs on a push to `main`, so confirm the `ai7uae-api` environment variables `GDELT_V2_READ_ENABLED=false` and `GDELT_ARCHIVE_REVIEW_ENABLED=false` **before** merge. Record the reviewed SHA, workflow run/attempt, immutable image digest, what-if and deployed revision. A merged branch is not proof of activation. The remaining fixes below require their own reviewed source promotion before either flag can be enabled.
2. Complete the article-evidence integration: select a source with documented URL/article matching, English and Arabic coverage, retrieval rights, retention terms and price; add a provider adapter with an allowlisted endpoint. Treat archived article URLs and returned text as untrusted. Do not fetch arbitrary publisher URLs from the API worker. Reuse the existing Gemini party-facts safeguards, require an exact quote in the supplied article text, and preserve an `unresolved` result for missing text, ambiguous identity, unsupported allegation or model failure. Wire the resolver into production startup, not just test injection.
3. Add a hard per-screening provider/Gemini spend cap, one-time cost reservation, bounded concurrency and a per-page execution deadline. Measure common-name subjects against the current 50-posting page and seven-day queue-message lifetime; a 10,000-step ceiling must end Inconclusive without losing the case. Make the runtime review flag a kill switch for **already queued** review jobs too: the current worker follows the persisted `archive_review_enabled` job field after the deployment flag is turned off. Define their terminal Inconclusive/callback behavior before release.
4. Close contract tests for crash/resume, duplicate delivery and charges, provider outage, stale/changed V2 snapshot, alias overflow, high-volume names, Search+ publisher preservation, owner isolation, evidence pagination, and JSON/PDF/callback agreement. Existing synchronous callers and version-2 queue jobs must keep their contracts. A confirmed direct adverse article must remain Unsafe even if another source is incomplete; Safe requires complete required source coverage and zero unresolved relevant articles.

**Files expected for Gate 1:** `lib/gdelt-archive-review.mjs`, `lib/ai7uae-gemini-adverse-api.mjs`, `lib/deep-research-queue.mjs`, `lib/adverse-media-report-store.mjs`, `server.mjs`, `lib/adverse-media.mjs`, `lib/adverse-media-report-pdf.mjs`, `api/openapi.json`, `test/gdelt-archive-review.test.mjs`, `test/gdelt-archive-review-api.test.mjs`, `test/deep-research-queue.test.mjs`, and affected API/report tests. Create `lib/gdelt-article-evidence-provider.mjs` only after the provider contract is approved. Any new secret must use the existing Key Vault path and be separately reviewed. Do not add another posting database, queue, job, or GDELT write grant to the API.

**Exit evidence:** reviewed provider contract and price; threat review of untrusted article text/URL handling; full tests and hosted CI; owner-scoped ledger and billing tests; a verified runtime kill switch. If any item fails, keep both flags off.

## Gate 2 — make the Azure archive complete and independently verifiable

1. With separately authorized production operations, read back the selected subscription, resource group, exact API/job image digests, two V2 tables, job identity and table permissions, private report storage, queue/dead-letter queue, current V1 and V2 watermarks, and the daily/weekly execution history. Stop on drift. The retained 20 November numbers are not a current inventory.
2. Use the reviewed digest on `main` and the existing [GDELT deployment workflow](../.github/workflows/deploy-gdelt-backfill.yml). After its what-if names only the expected jobs, set `GDELT_V2_DUAL_WRITE=true` for daily and weekly ingest. Check that a new daily interval produces a verified V2 manifest without changing V1 correctness. The archive backfill continues on its existing schedule; it cannot be skipped merely to obtain a wider marketing window.
3. Run the existing resumable `scripts/gdelt-index-v2-rebuild.mjs` against stored ZIPs, in bounded batches. Independently run `scripts/gdelt-index-v2-verify.mjs` over every interval. Compare V2 start/end and committed interval count to a **fresh** V1 watermark; check every ZIP digest/manifest/count and explain any gap. Do not edit the watermark by hand or treat a point-read count as historical completeness.
4. Compare paged V1 and V2 exact-name counts for at least 50 controlled subjects spanning zero, common, high-volume, Arabic/alternate-script and previously failing names. The last retained 7–47 ms point probes were against a partial V2 summary and are not a go-live latency result.

**Exit evidence:** fully contiguous verified V2 watermark covering the current V1 range, zero unexplained count differences in the parity cohort, daily/weekly job health and an operator-readable archive start/end. Any missing interval or summary mismatch keeps `GDELT_V2_READ_ENABLED=false`.

## Gate 3 — exercise the candidate without customer traffic

Use an internal-only candidate app and controlled, permitted subjects, as in the prior isolated run. Keep customer billing and the public route on the current production revision. Test standard and Search+ with the exact candidate digest, real Azure reads, real provider responses and an approved article-evidence adapter. Include clean, confirmed-adverse, ambiguous, namesake, Arabic, high-volume, stale-watermark, provider-429, and explicit historical date-gap cases. For each case retain a redacted request, source-attempt record, V1/V2 snapshot, article-decision counts, final JSON, PDF hash, callback delivery/verification result, profile and reviewer label. Retain private evidence only under approved rights; do not put article text or customer PII in CI artifacts.

Acceptance requires:

- No false Safe in the labeled set; every missing required source, unresolved article, count mismatch or cap is Inconclusive unless a confirmed direct adverse article makes the profile Unsafe. The profile has only Safe, Unsafe or Inconclusive.
- Undated all-stored requests use the verified Azure range and make zero public DOC calls. An explicit dated gap makes at most three direct public DOC attempts and retains Azure findings if they fail. Search+ retains base searches and adds publisher batches; record actual domains and failures.
- The review covers all V1 postings for a finished snapshot, deduplicates URLs, reconciles counts, and exposes every article decision through authenticated pages. A new daily interval or older backfill invalidates reuse. Owner B cannot read owner A's review.
- One final report and signed callback per job, with no repeated paid searches or duplicate customer charge on review-page, report or callback retry. PDF, JSON, evidence endpoint and callback agree on status, counts and reason codes.
- Measure cold first-review and warm reused-review p50/p90/p95/p99 separately from end-to-end API latency, plus provider calls, Gemini tokens, PDFs, Azure Table operations, backlog and cost per subject. Use the existing V2 lookup p95 target of 250 ms only for a ready exact-name point lookup; do not claim millisecond completion for article review. Set an end-to-end latency and spend ceiling from this measured baseline before production activation.

If the provider cannot supply enough article text to resolve plausible matches, do not enable archive review for customers. A metadata-only GKG mention cannot be cleared as Safe.

## Gate 4 — controlled production activation

1. Review the exact `main` SHA, digest and production `what-if`. The current API Container App uses **single active revision** and the V2/review flags are global, not workspace-scoped. There is no existing tenant-only production canary. Complete the isolated candidate first, then use a short, staffed production activation window; do not describe it as a limited-customer canary. If a true tenant canary is required, add and test an owner allowlist before this gate.
2. First activate only `GDELT_V2_READ_ENABLED=true`, keeping `GDELT_ARCHIVE_REVIEW_ENABLED=false`. Dispatch the existing production API workflow from reviewed `main`; verify the deployed digest and both runtime flag values. Run controlled standard/Search+ requests, check archive origin, snapshot and parity, and watch error rate, latency, Azure Table throttling, public-DOC attempts, cache invalidation and false-Safe indicators. Do not leave this state customer-wide if an evidence-pending V2 result materially changes eligibility unexpectedly.
3. After Gate 1–3 article review evidence is accepted, enable `GDELT_ARCHIVE_REVIEW_ENABLED=true` through the same reviewed workflow. Confirm worker and dead-letter readiness, provider secret availability without exposing values, review/paged-export owner isolation, cost reservations and signed callback delivery. Run one clean and one confirmed-adverse controlled job through standard and Search+; compare each final JSON, PDF and full evidence pages.
4. Monitor at least one daily ingest and one weekend backfill transition before broad promotion is called complete, because both change the archive snapshot and cache/review reuse. Watch queue age/depth, review pages per case, unresolved rate by reason, 429/5xx, dead letters, callback retries, p50/p90/p95/p99, Azure cost and provider spend. Record the release decision and exact observation window.

**Go/no-go:** the release owner, screening-policy owner, security owner and Azure operator sign off on the retained evidence and cost ceiling. Any unverified source window, false Safe, missing article rights, budget bypass, cross-owner evidence access, duplicate billing/callback or unexplained latency regression is no-go. Do not change public coverage wording to claim 12 months until the actual contiguous watermark reaches it.

## Rollback and recovery

- For a V2 lookup problem, set `GDELT_V2_READ_ENABLED=false` and redeploy the last reviewed compatible digest/configuration through the production workflow. Keep V1 ingest, raw ZIPs, manifests, report records and customer audit history intact.
- For article-review problems, set `GDELT_ARCHIVE_REVIEW_ENABLED=false` and use the **Gate 1 runtime kill switch** to stop already queued review work safely. Finalize affected jobs as Inconclusive with a signed callback, or hold them for an explicitly approved recovery; never silently mark them Safe. Verify queue/dead-letter state and any one-time charge adjustment.
- If the new API revision itself is faulty, restore a verified compatible prior digest through the reviewed workflow. Do not delete V2 tables or run a destructive rollback. Confirm active revision, flags and authenticated standard/Search+ behavior after recovery.
- Preserve the original request/result/report hashes, source snapshot, review ledger, cost records and incident timeline. Stop further activation if an unexpected production change appears in what-if or readback.
